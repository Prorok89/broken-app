# broken-app

Проект для демонстрации поиска и исправления багов, профилирования и оптимизации кода на Rust.

[Эталонный проект](https://github.com/Prorok89/reference-app)

## Изначальные проблемы

При старте проекта код содержал намеренные баги, Undefined Behavior (UB) и тяжелые алгоритмические неэффективности:

### 1. Undefined Behavior и ошибки памяти
*   **`sum_even`**: Ошибка выхода за границы массива (off-by-one) при использовании `unsafe` и `get_unchecked`.
*   **`leak_buffer`**: Утечка памяти (Memory Leak) из-за `Box::into_raw` без последующего `Box::from_raw`.
*   **`use_after_free`**: Классический use-after-free, приводящий к UB при освобождении `Box` и последующем чтении указателя.
*   **`race_increment`**: Data race (гонка данных) из-за использования `static mut` без атомарных операций.

### 2. Логические ошибки
*   **`average_positive`**: Неверный расчет среднего (деление на общую длину массива вместо количества положительных элементов). Также присутствовала потенциальная паника (деление на ноль) при отсутствии положительных чисел.

### 3. Алгоритмическая неэффективность
*   **`slow_dedup`**:  `sort_unstable()` внутри цикла на каждой итерации.
*   **`slow_fib`**: рекурсия без мемоизации.

## Внесенные изменения

### Исправление багов и UB
| Функция | Что исправлено |
|---------|----------------|
| `sum_even` | Исправлен диапазон цикла (`0..=len` → `0..len`). |
| `leak_buffer` | Добавлено корректное освобождение памяти через `Box::from_raw`. |
| `use_after_free` | Убрано разыменование после освобождения. |
| `race_increment` | Заменен `static mut` на `AtomicU64` (без `unsafe`). |
| `average_positive` | Исправлена логика фильтрации и добавлена проверка от деления на ноль. |

### Оптимизации
| Функция | До оптимизации | После оптимизации |
|---------|----------------|-------------------|
| `slow_dedup` | сортировка каждый раз | сортировка один раз + `dedup()` |
| `slow_fib` | рекурсия | итеративный подход |
| `leak_buffer` | Heap-аллокация `Box<[u8]>` | Итератор по срезу (0 аллокаций) |
| `average_positive` | Два прохода по массиву | Один проход через `fold` |

### Тестирование и нагрузочные испытания
1.  **Тесты**: Добавлены регрессионные тесты на каждый исправленный баг.
2.  **Инструменты анализа**: Код проверен с помощью Miri, Valgrind, ASan и TSan.
3.  **Бенчмарки**: Написаны тесты на Criterion (`benches/criterion_bench.rs`) для оценки производительности.

## Результаты нагрузочных испытаний (Criterion)

| Функция | До оптимизации | После оптимизации | Ускорение |
|---------|---------------|-------------------|-----------|
| **slow_dedup/10k** | ~10 000 µs | ~58 µs | **~170 000x** |
| **slow_fib/25** | ~45 000 ns | ~108 ns | **~400 000x** |
| **average_positive/50k** | ~500 µs | ~192 µs | **~2.5x** |
| **sum_even/50k** | ~300 µs | ~296 µs | Без изменений |
| **leak_buffer/100k** | ~450 µs | ~500 µs | +11% (но 0 аллокаций) |
| **normalize/long** | ~610 µs | ~690 µs | Без изменений |

*Примечание: `leak_buffer` и `normalize` показали незначительные регрессии, находящиеся в пределах погрешности замеров, однако `leak_buffer` полностью убрал лишние выделения памяти, что зафиксировано Heaptrack и Valgrind.*
